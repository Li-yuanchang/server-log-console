---
description: 不可用命令合集，避免 heredoc>、dquote> 等阻塞对话的 shell 写法
---

本 workflow 用于约束终端命令的提议与执行方式。
目标是避免命令进入等待补全输入、持续占用 stdin、无法自动结束或必须人工退出的状态，从而阻挡对话进度。

# 一律不可使用的命令模式

1. 未闭合引号的命令
   - 禁止任何会触发 shell 续行提示的写法。
   - 包括但不限于：`dquote>`、`quote>`、`bquote>`、`cmdsubst>`。
   - 示例：
     - `echo "abc`
     - `printf '%s\n' 'abc`
     - ``echo `date``

2. 未闭合 heredoc 的命令
   - 禁止任何会触发 `heredoc>` 的写法。
   - 示例：
     - `cat <<EOF`
     - `python <<'PY'`
   - 即使理论上可以继续补齐结束符，也不要使用这类需要多段输入的方式。

3. 依赖持续标准输入的命令
   - 禁止需要后续手动继续喂输入才能完成的命令。
   - 包括但不限于：
     - `cat > file`
     - `tee file`
     - `python`
     - `node`
     - `mysql`
     - `psql`
     - `sqlite3`
     - `bash`
     - `sh`
     - `zsh`

4. 默认不会自动退出的交互式程序
   - 禁止会进入全屏/交互界面并等待人工退出的命令。
   - 包括但不限于：
     - `vim`
     - `vi`
     - `nano`
     - `less`
     - `more`
     - `top`
     - `htop`
     - `watch`
     - `fzf`

5. 默认持续运行、会阻挡当前流程的命令
   - 禁止以阻塞方式运行不会自行结束的命令。
   - 包括但不限于：
     - `tail -f`
     - `journalctl -f`
     - `npm run dev`
     - `vite`
     - `next dev`
     - `pnpm dev`
   - 如果确实需要启动服务，必须使用不会阻塞当前对话的方式，并先检查是否已有现成服务可复用。

6. 需要人工确认、人工交互或人工退出的命令
   - 禁止依赖手动 `Ctrl+C`、手动输入 `EOF`、手动输入 `:q`、手动回答提示的问题型命令。
   - 包括但不限于：
     - `read`
     - `select`
     - 任意会弹出交互确认的 CLI
     - 任意需要进入 REPL 后再继续输入的 CLI

# 推荐替代方案

1. 写文件或改文件
   - 优先使用代码编辑工具。
   - 不要使用 heredoc、`cat > file`、交互式编辑器来写文件。

2. 执行一段脚本逻辑
   - 使用 one-shot 方式。
   - 例如：
     - `python -c "..."`
     - `node -e "..."`
     - `bash -lc "..."`
   - 要求命令本身一次执行完毕，不能等待继续输入。

3. 查看文件内容
   - 使用可自动结束的读取命令。
   - 例如：
     - `sed -n '1,120p' file`
     - `tail -n 200 file`
     - `head -n 100 file`

4. 查询数据库或命令行工具
   - 使用一次性参数执行。
   - 例如：
     - `sqlite3 db.sqlite "select * from table limit 20;"`
   - 禁止先进入 REPL 再继续输入。

5. 启动本地服务
   - 仅在确有必要时启动。
   - 必须避免阻塞当前流程。
   - 启动前先检查现有服务，避免重复启动。

# 执行前检查清单

在提议或执行任何终端命令前，必须先检查：

1. 这条命令会不会触发 `heredoc>`、`dquote>` 或其它 shell 续行提示。
2. 这条命令会不会等待用户继续输入内容。
3. 这条命令会不会默认持续运行且不能自行结束。
4. 这条命令会不会要求人工退出、人工确认或进入交互界面。
5. 这条命令能不能改写为单次执行、自动结束的 one-shot 形式。

只要以上任一问题答案为“会”，就不要使用该命令，改用安全替代方案。
