## 1. `.class` 与压缩包内容预览

### 背景与价值

- 当前文件浏览器和日志搜索默认按文本处理，遇到 `.class` 会出现乱码或直接打不开
- `.zip/.jar/.war/.ear` 只看目录没有实际排障价值，用户需要像好压/IDEA 一样进入归档并预览真实文件内容
- 实际排障场景里经常需要：
  - 看一眼某个版本的 `.class` 是不是带上了某个修改
  - 直接查看 jar/war 内部的配置、前端静态文件、Manifest、class
  - 在多个 `.class` 里搜某个字符串常量、方法名、类名
  - 在堡垒机里没有 IDE，只能远程查看时尤其需要

### 当前状态

- 已避免 `.class/.zip/.jar/.war/.ear` 进入日志切片 viewer，改走 `POST /api/files/preview`
- 已有 ZIP 中央目录读取能力：只读中央目录，不解压远程目录，不修改服务器
- 已有 class 元数据解析能力：文件头、版本、类名、父类、接口、字段、方法签名
- 待增强：归档内单文件真实内容预览、归档内 class 反编译源码预览

### 技术路径

总思路：**归档浏览器负责导航和条目内容读取，class 预览默认展示反编译源码，失败时回退元数据。**

#### 当前实施阶段：归档条目内容预览

- 新增接口：`POST /api/files/archive-entry-preview`
- 请求参数：`serverId`、`filePath`、`entryName`
- 网关读取 ZIP 中央目录，定位目标 entry 的 local file header 和压缩数据
- 支持方法：
  - `0` store：直接读取原始字节
  - `8` deflate：Node `zlib.inflateRawSync` 解压
- 不做远程解压，不写临时目录，不污染服务器
- 条目大小做上限控制，避免一次性拉取过大 entry 卡住 UI
- 前端表现：
  - ZIP/JAR/WAR/EAR 预览表格里的文件行可点击
  - 点击普通文本文件：在右侧/下方显示真实内容
  - 点击 `.class`：走反编译/元数据视图
  - 目录行只导航/过滤，不请求内容

#### 当前实施阶段：`.class` 反编译源码

- 默认反编译器：CFR 单 jar
- 原因：
  - GitHub 开源，MIT 协议
  - 单 jar，集成成本低
  - Java 6+ 可运行，服务器或本机兼容性更好
- 打包方式：
  - `apps/gateway/resources/decompilers/cfr.jar`
  - Electron 打包时复制到 gateway runtime
- 执行策略：
  - 优先本地 gateway 侧执行 `java -jar cfr.jar <class>`
  - 远程 `.class` 先下载到本地临时文件，归档内 `.class` 先从 entry 解压到本地临时文件
  - 反编译失败、无 Java、无 jar 时回退到当前元数据解析
- 后续可选升级：
  - Vineflower/Fernflower 作为第二反编译器，提高 Java 17+ 新语法还原质量
  - 反编译结果缓存，避免重复点击同一 class 反复执行

#### 后续阶段：归档浏览体验接近好压/IDEA

- 增加归档内路径面包屑和目录树
- 增加文件名搜索/过滤
- 增加图片、JSON、XML、properties 的更友好预览
- 增加单个 entry 下载能力
- 增加 jar/war 内 class 搜索与反编译后搜索

#### 阶段 1：MVP，远程 `javap`

此方案暂不作为默认实现，仅作为无本地 Java 反编译器时的备用方向。

- 触发条件：viewer 打开扩展名是 `.class` 的文件
- 网关在远端执行：
  - `javap -p -c -l <path>`：方法签名 + 字节码 + 行号
  - 失败回退：`strings <path>` 抓字符串常量
- 对前端表现成"普通文本文件"，复用现有 slice/搜索管线
- 优点：几乎所有 Java 服务器都自带 `javap`，零额外依赖
- 缺点：bytecode 不如 Java 源好读

#### 阶段 2：进阶，远程 CFR 反编译

此方案暂不作为默认实现。默认使用本机 gateway 侧 CFR，避免往远端上传工具 jar。

- 内置 `cfr.jar`（单文件，约 2MB），首次使用时上传到远端临时目录
- 远端执行：`java -jar /tmp/slc-cfr.jar <class file>`
- 输出近似 Java 源，可读性高，搜索命中也更接近"真实代码"
- 失败回退到阶段 1 的 `javap`
- 依赖：远端有 `java`（绝大多数 Java 服务器满足）
- CFR 也可换 Procyon/Fernflower，但 CFR 单 jar、零依赖、命令最干净

#### 阶段 3：复合归档，`.jar` / `.war` 浏览

当前已开始做本地 gateway 侧的归档浏览，不采用远端 `unzip -l` 作为默认路径。

- viewer 看到 `.jar/.war/.ear` 时：
  - 用 `unzip -l <file>` 列条目，前端展示成虚拟目录
  - 选中某 `.class` 时，远端 `unzip -p <jar> <entry> > /tmp/xx.class` 后走阶段 1/2 流程
- 多文件搜索：调用现有 `apiCreateSearchTask`，但搜索器扩展为：
  - 命中 `.class` → 先 `javap -p`（或 CFR）再匹配
  - 命中 `.jar` → `unzip -p` 拿到所有 `.class` 流式喂给匹配器
- 这条路径相对重，建议单独立项再做

#### 多文件搜索的快速版

- 场景：用户只想在一堆 `.class` 里找一个字符串常量（如类名、表名、SQL 片段）
- 网关侧最低成本实现：`for f in *.class; do strings "$f" | grep -H "$kw"; done`
- 命中后再点击进入阶段 1/2 的详细查看
- 适合作为搜索框对 `.class` 的兜底实现，不依赖 `java` 也能工作

### 风险与依赖

- 本机 gateway 所在环境需要 `java` 才能执行 CFR；无 Java 时必须明确回退元数据，不要静默失败
- CFR jar 需要纳入打包资源，打包脚本必须验证复制成功
- `javap` / `CFR` 输出体积可能远大于源 `.class`，需要复用现有 slice 分片，不要一次拉完
- 反编译耗时不稳定，单文件点击可同步等待，但多文件搜索必须复用搜索任务异步管线
- ZIP 条目读取必须限制大小，且只支持常见压缩方法；遇到加密或未知压缩方法要明确提示
- 大目录全量解码会拖慢搜索任务，需在搜索前端配 `仅搜文本/同时搜 .class` 的开关，默认关闭

### 验收

- 单文件场景：远程 `.class` 弹窗默认展示反编译源码；失败时展示元数据和失败原因
- 归档场景：`.zip/.jar/.war/.ear` 内文件行可点击，文本文件能看到真实内容，`.class` 能看到反编译源码或元数据回退
- 多文件场景：搜索结果列表里能看到 `.class` 命中行，点击能进入解码后的视图
- 异常场景：远端没有 `java/javap` 时给出明确提示，不要静默失败

## 2. 低频工具区能力

以下能力组件当前已通过 `UtilityWorkspace` 接入主工作台，属于低频但可用的辅助能力。后续优化重点不是“接回入口”，而是控制复杂度、避免干扰日志阅读主链路。

### 2.1 DiffComparePanel（本地文件对比）

- **组件**：`apps/extension/src/ui/DiffComparePanel.tsx`
- **当前入口**：`UtilityWorkspace`
- **优化方向**：
  - 内容标准化（行尾、Tab、BOM）必须先做，否则误报会回来
  - 长行/超大文件需分块对比，整文件一次塞 Monaco 风险高
  - UI 不再嵌回 viewer 主区，保持在工具区内，避免污染日志阅读布局

### 2.2 SshTunnelPanel（SSH 隧道管理）

- **组件**：`apps/extension/src/ui/SshTunnelPanel.tsx`
- **样式**：`styles-viewer-search.css` 仍保留 `.ssh-tunnel-*`
- **接口**：`POST /api/ssh/tunnel`、`DELETE /api/ssh/tunnel/:tunnelId`、`GET /api/ssh/tunnels` 仍在网关
- **当前入口**：`UtilityWorkspace`
- **优化方向**：补充端口占用提示、隧道状态刷新、关闭失败时的明确反馈

### 2.3 BatchCommandPanel（批量命令）

- **组件**：`apps/extension/src/ui/BatchCommandPanel.tsx`
- **接口**：`POST /api/batch/exec` 仍在网关
- **当前入口**：`UtilityWorkspace`
- **优化方向**：增加危险命令提示、输出筛选、失败结果聚合

### 2.4 通用注意

- 三个面板继续复用 `UtilityWorkspace` 容器，不要再各自写一套独立窗口
- 主题适配按 `docs/style-architecture.md` 的"局部 class + `.theme-modern` 同级覆写 + SVG 显式继承色"三件套处理
- 改动前先在 `docs/业务功能总览.md` 和 `docs/架构与修改地图.md` 里确认"入口位置 → 组件 → 网关接口"的链路条目
