# 功能介绍

## 1. 产品定位

Server Log Console 是一个面向研发、测试、实施人员的日志工作台。它不是简单把 `grep` 包进浏览器，而是把服务器连接、日志检索、实时追踪、片段下载、大文件切片浏览整合成一个可直接操作的中文界面。

核心目标有三个：

- 快速定位指定关键字、单号、SQL、异常栈
- 在不下载整份大日志的前提下查看上下文
- 在测试与开发环境中安全地复用 FinalShell 连接信息

## 2. FinalShell 自动导入

系统可以直接读取本机 FinalShell 连接配置，自动识别常见的 macOS、Windows、Linux 配置目录，并把连接信息导入到本地网关。

为了避免“每台机器路径都不一样”的问题，当前版本支持两种导入方式：

- 自动检测常见 FinalShell 目录
- 用户手动指定 FinalShell `conn` 目录

系统会把“当前配置的 FinalShell 目录”和“上次成功导入时间”持久化保存到本机配置目录。用户下次打开时，不需要重新填写。

导入后可保留以下信息：

- 服务器名称
- 主机地址与端口
- 用户名
- 分组路径
- 认证类型
- 是否存在本地已保存密钥或密码

当前版本已经支持解密导入 FinalShell 中的密码型口令。私钥型配置也已补上候选路径扫描框架，但由于本机样本里暂未发现真实私钥配置，仍需真实样本继续验证。

这样做的价值是避免重复维护连接清单，也让浏览器端的服务器列表与运维同学习惯的 FinalShell 视图保持一致。

## 3. 连接凭证管理

连接凭证不应该让用户靠猜，因此当前版本把“凭证来源”和“凭证可用性”显式展示在界面里。

系统会按以下优先级识别凭证来源：

- 手动保存到本地的用户名、密码、私钥
- 从 FinalShell 导入到当前会话的连接信息
- 本地网关进程配置的环境变量默认凭证

界面会直接展示：

- 当前服务器用户名
- 是否已存在密码
- 是否已存在私钥
- 当前凭证来自哪里
- 是否可以直接尝试连接

同时支持“测试连接”：

- 实际发起 SSH 连接
- 检查目标日志目录是否可读
- 返回示例目录条目
- 把失败原因直接展示给用户

对于内网目标机，当前网关已补上“直连优先，失败后尝试堡垒机二跳”的基础能力。如果二跳仍失败，返回信息会同时说明直连失败原因和堡垒机失败原因，方便快速判断到底是目标机问题还是堡垒机凭证问题。

如果同一环境存在多个堡垒机入口，用户也可以在设置中为当前服务器手动指定优先使用哪一台堡垒机。该绑定会保存到本机，刷新页面后仍然生效。

如果 FinalShell 已导入但实际连接失败，界面会明确提示用户：当前读取到的可能是 FinalShell 的加密口令，需要手动补录真实 SSH 密码或私钥。

手动保存的连接凭证会持久化到本机配置目录，页面刷新后不会丢失。

本机配置当前包括：

- 手动维护的服务器列表
- 手动保存的用户名、密码、私钥
- FinalShell 手动指定目录
- FinalShell 上次成功导入时间

## 4. 安全边界

为了避免误操作，产品会把 FinalShell 中分组路径包含“生产”的连接标记为谨慎目标，但不再强制过滤。

当前策略是：

- 允许导入并展示生产分组连接
- 不在系统内部做任何“自动帮你连生产”的动作
- 是否执行连接与检索，由用户显式选择和触发

这意味着“生产”只是提示信息，而不是硬性禁止规则。

## 5. 历史日志检索

用户可在界面中选择或填写以下查询条件：

- 目标服务器
- 日志文件路径
- 指定日期
- 关键字、业务单号、表名、SQL 片段

本地网关会基于这些结构化条件生成远程检索命令，通过 SSH 在目标机器上执行，再把结果返回给前端。前端会同时展示：

- 原始检索输出
- 命中条目数量
- 当前检索状态
- 临时结果标签页，便于继续二次筛选
- 最近一次搜索条件自动记忆，并支持“恢复上次”

适合处理的典型场景包括：

- 查询 `TRAVEL_SPECIAL_SUBSIDY` 插入语句
- 定位某个 `REIMBURSEMENT_ID` 的上下文
- 检索报错关键字如 `NullPointerException`、`Duplicate entry`
- 按日期筛选某天日志，再搜索指定业务号

## 6. 远程目录浏览

很多时候用户并不知道完整日志路径，因此系统支持远程目录浏览，并逐步弱化手工输入路径的方式。

浏览能力包括：

- 查看远程目录下的子目录和文件
- 识别文件与目录类型
- 展示文件大小
- 点击文件后自动回填到当前检索路径
- 在当前目录内按文件名关键字快速筛选

这样可以减少手动输入路径出错的问题，也便于在不同机器上快速定位日志目录。

## 7. 实时日志追踪

除了历史检索外，系统还支持实时日志流查看。

实现方式是：

- 前端通过 WebSocket 建立实时会话
- 网关通过 SSH 执行 `tail -F`
- 新增日志内容持续推送到浏览器界面

实时追踪面板提供：

- 连接状态展示
- 自动重连
- 手动停止
- 片段下载

适合用于复现问题时边操作边看日志，或者观察某个关键字是否再次出现。

## 8. 日志片段下载

系统支持两类下载：

- 历史检索结果下载
- 实时日志片段下载

这对问题留痕、工单附证、群内沟通都很有帮助。用户不需要再手工复制终端内容，也不必把整份巨大的源日志传来传去。

## 9. 大日志切片浏览

线上和测试环境中的日志文件往往达到 GB 级，浏览器无法直接承载整文件读取。因此系统新增了大日志切片能力。

当前支持：

- 读取日志文件元信息
- 获取文件大小与修改时间
- 按 `offset + length` 读取指定字节范围
- 自动尽量按完整行裁切返回
- 支持向前一段、重新加载、向后一段、跳到尾部
- 支持从结果页继续筛选，并保留原始行号定位信息

这套能力接近大文件编辑器的“分段打开”思路，能显著降低内存占用，也让日志定位速度更可控。

## 10. 多平台兼容

当前方案重点兼容以下桌面环境：

- macOS
- Windows
- Linux

兼容内容包括：

- FinalShell 配置目录自动发现
- 浏览器插件界面访问
- 本地网关运行
- 通过 SSH 连接 Linux 服务器检索日志

如果用户使用了自定义 FinalShell 目录，也可以通过环境变量覆盖默认发现路径。

## 11. 当前范围与后续方向

当前版本已经覆盖“导入连接、搜索、实时查看、下载、切片浏览”这条主链路，但仍有若干增强空间：

- 按日志类型内置搜索模板
- 搜索命中后直接跳转对应切片偏移
- 保存常用检索方案
- 接入更安全的凭据管理方式
- 增加审计记录与协作分享能力

整体来说，这个产品已经具备日志快速定位工具的雏形，下一步重点是继续把大日志体验、查询模板和产品细节打磨到更接近专业日志分析工具的水准。
