# 在线更新与打包方案（V0 · 设计稿）

更新时间：2026-10-02 · 状态：**设计阶段，未实施**
配套原型：`docs/prototypes/update-center-v1.html`（交互原型，数据为模拟）
参照项目：`~/Git/GitHub/virtual-resource-console`（下称 VRC）的在线更新实现

---

## 1. 背景

当前本项目发版完全依赖手工：`npm run release:mac`（构建 + 本地 `/Applications` 安装），远程用户、Chrome 扩展用户无法在线获得新版本。目标是对齐 VRC 的体验：

- 用户在**设置中心 → 软件更新**里检查新版本、查看版本说明、下载（带进度与校验）、重启安装；
- 发布侧一条命令汇总产物并生成清单/校验和，上传到内网更新源即完成发布；
- Chrome 扩展与 Web 版按各自机制跟进（P1/P2）。

## 2. VRC 实现摘要（借鉴点）

| 环节 | VRC 做法 | 借鉴 |
|---|---|---|
| 更新源 | API 静态托管 `desktop-updates/` 目录（`latest-mac.yml`、安装包、`.blockmap`、`SHA256SUMS`），无数据库 | ✅ 直接沿用：静态目录 + no-cache 清单 / immutable 安装包 |
| 检测 | electron-updater `generic` provider，`autoDownload=false`，semver 对比 | ✅ 沿用 |
| 状态机 | `idle/checking/unavailable/up-to-date/available/downloading/ready/error`，IPC 广播到渲染层 | ✅ 沿用（命名改 `slc:update:*`） |
| 安装 | `quitAndInstall()` 重启安装，`autoInstallOnAppQuit=true` 兜底 | ✅ 沿用 |
| UI | 设置页「更新」面板：状态徽标、进度条（字节级）、版本说明、自动检查开关、红点提醒 | ✅ 对齐本方案原型 |
| 发布 | 本地脚本汇总产物 + 校验版本一致性 + SHA256SUMS，**人工 ssh 上传，清单最后传** | ✅ 沿用（个人/内网工具够用，不做服务端发布 API） |
| 失败处理 | check 失败降级为 `unavailable` 而非 error；错误码映射中文提示 | ✅ 沿用 |

VRC 没有、本方案补充的点：

1. **版本三处不一致问题**：本项目 `apps/electron/package.json` 为 0.3.238，扩展 `manifest.json` 停在 0.1.0。方案要求构建时从 electron 包注入扩展版本，消除双版本。
2. **Chrome 扩展自托管更新**（`extension-update.xml` + zip），VRC 走企业策略 crx，本项目以 zip 侧载 + update.xml 为 P1。
3. **Web/网关形态**的版本可视化（P2）。

## 3. 形态与更新方式矩阵

| 形态 | 检测依据 | 生效方式 | 阶段 |
|---|---|---|---|
| 桌面版（Electron，主形态） | `latest-mac.yml` / `latest.yml` | 下载 → 重启安装（退出兜底） | **P0** |
| Chrome 扩展（MV3） | `extension-update.xml` | 浏览器扩展更新机制拉取 zip/crx | P1 |
| Web 版（网关托管 dist） | `manifest.json` | 服务端替换资源，刷新生效（仅展示版本） | P2 |
| UI 热更新（不重装壳） | `manifest.json` | 网关替换 `extension/dist`，重启窗口 | P2 可选 |

## 4. 总体设计

### 4.1 更新源（静态目录）

```
<更新主机>/desktop-updates/
├── manifest.json                      # 自汇总清单：版本/渠道/说明/各形态文件索引
├── latest-mac.yml / latest.yml        # electron-updater 官方清单（最后上传）
├── ServerLogConsole-<ver>-arm64.dmg (+.blockmap)
├── ServerLogConsole-<ver>-win.zip  / Setup.exe (+.blockmap)
├── slc-web-<ver>.tar.gz               # UI+网关增量包（gateway/dist + extension/dist）
├── server-log-console-extension-v<ver>.zip
├── extension-update.xml               # 扩展更新清单（P1）
└── SHA256SUMS
```

- 优先由**更新主机上的网关/nginx** 静态托管；桌面端更新源地址来自打包前写入的资源 `resources/update-config.json`（env `SLC_UPDATE_URL` 可覆盖，开发态读 `.env.local`）。
- 缓存策略与 VRC 一致：`latest*.yml`、`manifest.json`、`extension-update.xml` 为 `no-cache`，安装包 immutable。

### 4.2 版本号统一（必须先做）

- **唯一版本源：`apps/electron/package.json`**（`predist` 已由 `bump-version.cjs` 自动 +1 patch）。
- `apps/extension` 构建时（vite define / 插件）把该版本写入 `manifest.json` 与 `window.__APP_VERSION__`，删除扩展包里手写版本。
- 发版同时更新 `CHANGELOG.md` 顶部条目；`release:update` 脚本强校验三者一致，不一致直接失败（防"文件名新版、内容旧版"）。

### 4.3 客户端（桌面端 P0）

文件落点：

- `apps/electron/main.cjs`：新增 `configureDesktopUpdater()` + `desktopUpdateState` 状态机 + IPC（`slc:update:get-state / check / download / install`，推送 `slc:update:state`）。
  - 可用性门槛：已打包 && 配置了更新源 && （macOS zip/dmg 或 Windows NSIS 安装版）；portable/免安装版提示不支持。
  - `autoDownload=false`；`autoInstallOnAppQuit=true`；错误码映射中文（校验失败 / 签名 / 404 / 网络）。
  - 启动自动检查：仅在开启「自动检查」且本次会话未检查过时执行一次；结果只做红点提醒。
- `apps/electron/preload.cjs`：暴露 `window.slcDesktopUpdate`。
- UI（`apps/extension`）：
  - 设置中心 rail 新增第三项「软件更新」（`SettingsWorkspaceView` 增加 `"update"`），面板结构按原型：状态主卡（版本、宿主徽标、主按钮、进度条、SHA-256 行）、版本说明卡、更新设置卡（自动检查 / 渠道 / 更新源+测试）、各形态说明卡、检查记录、关于本软件。
  - 红点：`available/downloading/ready` 时在设置入口与 rail 显示（对齐 VRC `hasPendingDesktopUpdate`）。
  - Web / 扩展宿主：面板只读展示服务端版本 + 各自更新提示（对齐 VRC 文案策略）。
- 状态持久化：`自动检查` 开关存 localStorage（键 `slc.update.auto-check`），与 VRC 一致。

### 4.4 发布流水线（`scripts/prepare-online-update-release.mjs`，npm script `release:update`）

1. 校验版本一致性（electron 包 = CHANGELOG 最新 = 扩展 manifest 构建产物）。
2. 收集 `apps/electron/dist` 产物（dmg/zip/exe + `latest*.yml` + `.blockmap`）到 `release/online-update-<ver>/desktop-updates/`。
3. 打 `slc-web-<ver>.tar.gz`（`gateway/dist` + `extension/dist` + 生产依赖）。
4. 复制扩展 zip（现有命名 `server-log-console-extension-v<ver>.zip`）。
5. 生成 `manifest.json`（含 releaseNotes，取自 CHANGELOG 对应版本条目）与全目录 `SHA256SUMS`。
6. 打印上传指引：**先安装包/增量包，最后 `latest*.yml` + `manifest.json`**，附 rsync 与 curl 抽查命令（见原型「发布流程」页）。

### 4.5 API 清单（更新主机网关）

| 路径 | 方法 | 作用 |
|---|---|---|
| `/desktop-updates/*` | GET/HEAD | 静态托管更新清单与安装包（防路径穿越；流式发送） |
| `/health` | GET | 健康检查（Web 版可顺带返回服务端版本，P2） |

## 5. 实施步骤

1. **P0-a 版本统一**：构建注入扩展版本；`release:update` 骨架（校验 + SHA256SUMS）。
2. **P0-b 桌面端更新**：main.cjs 状态机与 IPC、update-config 资源、更新源静态托管；mac 先行（dmg/zip），Windows NSIS 跟进（`differentialPackage` 默认关，先全量）。
3. **P0-c UI**：设置中心「软件更新」面板 + 红点 + 启动自动检查（按原型实现）。
4. **P1 扩展**：`extension-update.xml` 托管 + 扩展内「检查扩展更新」入口。
5. **P2 Web/热更新**：Web 版版本展示；网关自替换 `extension/dist` 的热更新链路。

## 6. 风险与对策

- **更新源不可达**：check 失败降级 `unavailable`，UI 显示"更新源不可达"而非报错弹窗；更新源地址可被 env 覆盖，便于切换主机。
- **清单与包不同步**：上传顺序强制（包先、清单后）+ 脚本输出 curl 抽查步骤；`SHA256SUMS` 全目录校验。
- **macOS 签名/公证**：当前未公证，用户侧 Gatekeeper 提示与 electron-updater 无强依赖（zip/dmg 直装）；后续若启用签名需把公证纳入 dist 流程。
- **同版本号重发**：禁止；脚本校验 CHANGELOG 版本必须严格大于上一发版。
- **Windows 免安装版**：明确提示不支持自动更新（对齐 VRC 判定 `Uninstall *.exe` 的逻辑）。
