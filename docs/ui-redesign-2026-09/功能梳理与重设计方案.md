# UI 整体重设计 — 功能梳理与方案

更新时间：2026-09-29
状态：梳理完成，原型逐屏产出中（`prototype.html`，左上角索引切换屏幕）

## 0a. 实测证据（2026-09-29，web 端 5173 实测）

- **侧栏常驻 54 个按钮**：无障碍树显示 27 行服务器每行都挂着「管理」「删除」两个按钮（视觉上悬浮才出现），键盘 Tab 遍历要跳过 54 个隐藏按钮才能到主内容。
- **任意忙碌 → 全工具栏禁用**：连接一台服务器期间，日志/文件切换、搜索框、8 个文件操作按钮、状态、录制、更多条件**全部 disabled**——连接耗时被放大成全界面不可用。
- **双"日志控制台"标题**：DOM 里 eyebrow 与 h1 都是"日志控制台"（其一 display:none），结构冗余。
- **传输记录弹窗**（用户截图）：空数据渲染 6 张统计大卡 + 全屏遮罩；6 个过滤器同时展示但 5 个为 0。
- **工具入口分散**：隧道/批量/状态/对比各一个面板类，入口藏在不同位置（工具行 ⋯ / 侧栏），无统一发现路径。
- **检索条件无记忆分组**：8 个条件控件平铺一行，超出折叠到"更多条件"，但折叠项与常驻项没有频率分层。

## 0. 设计基调（延续已确认的方向）

- **全白通栏 + 1px 细线分隔**：无灰底画布、无四周留白，面板齐平（主界面既有皮肤，已与用户对齐）
- **密度统一**：行高 40±6px、正文字 12.5px、辅助字 11px，所有界面同一套
- **弹窗降级**：全屏大弹窗只保留"设置中心"和"文件预览"两个；其余全部改为轻量承载
- **一切控件有语义**：图标语义对齐 lucide 惯例；可点的值有 pill/控件形态，不可点的没有
- **颜色即状态**：蓝=主操作/选中，绿=在线/成功，红=危险，橙=告警；无装饰性色块

## 2. 最重要的三个结构性决策

1. **「工具抽屉」取代四类弹窗**：传输记录、SSH 隧道、批量执行、服务器状态、本地对比统一为**右侧滑出抽屉**（宽 420px，全高，ESC 关闭）。它们都是"查看/轻操作"性质，不值得全屏弹窗。
2. **终端升级为工作区 tab**：与「日志预览」「文件目录」平级，替代现有底部面板/浮层/分离三态并存。
3. **搜索条件两段式**：常驻一行（关键字 + 时间范围 + 检索），高级条件（排除/正则/上下文/预设）收进右侧抽屉，与工具抽屉同一交互语言。

## 3a. 核心功能优先级（v2 修订）

**本项目核心 = 日志排障链路**：选服务器自动连接 → 关键字检索 → 命中阅读（仅命中/含上下文）→ 命中跳转切片定位 → 实时接力观察 → 终端验证操作。设计权重必须向这条链路倾斜：

- S14「排障动线」以四段 storyboard 把完整链路画出来，作为实施时的主验收线
- 其余屏（文件/传输/工具/设置）都是链路的支撑设施，交互语言必须服从主线

## 3c. 优化点补充（上轮遗漏，按价值排序）

1. **搜索历史与条件收藏**：最近 20 条检索历史下拉 + 命名收藏（配合预设）

## 3d. 窗口适配规范（review 反馈补充，实施必须遵守）

| 断点 | 行为 |
|------|------|
| ≥ 1440 | 侧栏 240 · 设置清单 268 · 抽屉 420 推挤式（内容收窄不遮盖）· 文件树常驻 |
| 1024 – 1440 | 侧栏 200 · 抽屉覆盖式（带遮罩，点击遮罩关闭）· 文件树常驻 |
| 800 – 1024 | 侧栏折叠 56px 图标列（悬浮展开全名）· 文件树隐藏改下拉 · 抽屉覆盖式 |
| < 800 / 最小尺寸 | 表格隐藏「类型」列 · 工具栏搜索框收缩为图标浮层 · 终端分屏改上下堆叠 |
| PiP | 默认 980×680，最小 720×420；内容随宽度降级（隐藏次要按钮） |

**分隔线单边框原则**：所有面板分隔线统一 `1px solid var(--line)`；相邻面板禁止双边框叠放（左 pane 不设 border-right + 右 pane border-left）。根因案例：S8/S9 原型里左 pane border-right 与抽屉 border-left 叠成 2px。应用内现存 2px 边框 3 处（transfer 弹窗样式【已随弹窗删除】、终端分屏分隔【拖拽把手，保留】、设置锚点指示【状态指示，非分隔线，保留】）。

**抽屉非模态原则**：抽屉（传输/工具）是伴生面板——**无遮罩、不变暗、不锁主界面**，右侧监控/传输时左侧检索、看日志、操作文件照常进行。模态只保留两处：设置中心（互斥全屏，用户明确要求）与文件预览（弹窗）。`Drawer` 组件实现已按此（无 backdrop，ESC 关闭）。

**流式布局与单行原则**：控件永不内部换行（按钮/chip/pill/分段全部 `white-space:nowrap` + 图标文字 flex 单行；曾因 svg display:block 堆叠到文字上方，已修）。空间不足时的收缩顺序：① 标题截断省略 → ② 控件缩 padding → ③ 次要按钮隐藏进 ⋯ 菜单 → ④ 最后才考虑换行/隐藏。可变面板用 flex + min-width:0 收缩，禁止写死宽度导致溢出换行。

## 3f. 架构设计：积木式功能组装（组件化 · 策略化 · 可配置）

### 现状病灶（为什么必须调）

- `App.tsx` 4000+ 行、60+ useState、20+ hook 手工接线，props 钻孔 5-8 层
- 功能之间靠"都在 App 里"耦合：摘掉终端、换掉检索实现都要动核心文件
- 弹窗/面板/工具各自为政，无统一注册与出口（D7）

### 目标结构（功能 = 积木，壳 = 装配）

```
apps/extension/src/
├── app/                      # 壳（薄装配层，目标 <500 行）
│   ├── AppShell.tsx          # 布局骨架：Sidebar + Workarea + DrawerHost + OverlayHost
│   └── registry.ts           # 注册表：视图 / 抽屉面板 / 命令 / 快捷键 的唯一装配点
├── core/                     # 与业务无关的底座
│   ├── stores/               # 轻量 store slices：server / session / pref / transfer
│   ├── api/                  # 网关客户端（现 api.ts 迁入）
│   └── design/               # tokens.css（与应用同源）+ 基础组件 Button/Chip/Drawer/Menu/Input…
├── features/                 # 功能积木，每个可独立存在
│   ├── server-list/          # 侧栏
│   ├── log-search/           # 检索（search-strategy 策略）
│   ├── log-slice/  live-follow/  terminal/  file-browser/
│   ├── file-preview/         # preview-strategy：text / archive / class
│   ├── transfer/  tools/  settings/
└── shared/                   # 纯函数
```

### 三条原则

1. **组件化**：`core/design` 出基础组件，`features/*` 出功能组件；跨 feature 只走 registry/公开 API，禁止深路径互引。App.tsx 只剩"把积木装进壳"。
2. **策略化**：把已验证的策略模式推广到全应用——连接策略（direct/bastion，已有 strategy-resolver）、预览策略（text/archive/class）、检索策略（单文件/多文件/本地）、传输通道策略。策略 = 注册表 + 统一接口，新增一种 = 注册一项，不改核心。
3. **可配置**：偏好设置 = schema 驱动（字段声明 → 自动渲染表单 + 自动持久化，S14 的水印/动效就是新增两个字段声明）；工具抽屉 = panels 注册数组；快捷键 = 映射表。加功能从"改代码"变成"加配置/注册项"。

### 状态规则

- 跨 feature 共享 → store slice（替换 props 钻孔）；feature 内部 state 不上 store
- 先迁两个最小的（pref / transfer）验证模式，再逐个搬

### 迁移路径（增量，不停机，每步可验证）

1. 抽 `core/design` tokens + 基础组件（纯新增，零风险）
2. store slices 替换 props 钻孔（pref、transfer 试点）
3. features/ 逐个搬家，每搬一个 = 一个可验证版本；App.tsx 同步瘦身
4. registry 上线：工具抽屉（S9）与视图切换直接由注册表驱动
5. 完成态：App.tsx < 500 行，新功能 = 新增一个 feature 目录 + registry 注册

## 3g. 样式 100% 还原机制

1. **令牌同源**：原型与 `theme-modern.css` 使用同一套 CSS 变量名（--panel/--ink/--accent/--line/--r-s…）。实现时组件样式**只允许用 token**，禁止裸色值（THEME-SPEC 既有规则，本阶段严格执行 + code review 把关）。
2. **组件级还原**：`core/design` 基础组件的样式直接从原型 CSS 移植（原型即样式规格），原型里的每个控件 = 实现里的一个基础组件。
3. **七态验收**：每个交互组件验收 hover / active / disabled / focus / 空态 / 加载态 / 错误态。
4. **像素对照**：实现后与原型同视口（1440×900）截图并排比对，布局偏差 ≤ 2px、颜色取值一致。
5. **细节检查清单**（本轮沉淀）：控件单行不换行 · 流式收缩顺序 · 分隔线单边框 · 关键信息滚动不省略 · 0 计数隐藏 · 空态模板 · 窗口断点表（S15）。

## 4. 验证流程

1. 用户逐屏 review 原型 → 每屏给"通过 / 改 X"结论
2. 全部确认后按屏实施，每屏一个可验证的版本
3. 实施顺序建议：S8/S9（抽屉，独立性强）→ S3/S4（检索主链路）→ S5（终端 tab）→ S1/S2（框架收口）→ S6/S7（文件链路）→ S11/S12（外围）
