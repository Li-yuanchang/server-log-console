# 检索体验调整方案（2026-09-30）

针对反馈的三个问题：① 进度区平白多一行「全文扫描」；② 检索内容与输入不一致；③ 检索太慢、等半天。
另按新要求：结果区左侧大片空白（原为时间戳列）在无时间戳时应去掉。

---

## 1. 「全文扫描」平白多一行 —— 独立进度面板

**现象**：检索时按钮下方出现一整行进度条 + 折叠面板，写着「全文扫描 · 阶段 x/y」。

**根因**：`SearchProgressPanel`（`<details>` 折叠面板）在 `searchStartedAt` 期间常驻渲染于工具栏下方，与
「S13 原型：进度内联在检索按钮上」的设计冲突——原型的进度是**内联按钮**（`340MB/1.2GB`），不是独立一行。

**调整**：
- 删除 `SearchProgressPanel.tsx` 及其在 `App.tsx` 的渲染块、相关 label 计算（`searchProgressPhaseLabel` /
  `searchOverallProgressLabel` / `searchPhaseProgressLabel` / `searchProgressMatchLabel` / `liveStrategyLabel`）。
- 同步删除其 CSS（`styles-responsive.css` 第 26–163 行整块、`theme-modern.css` 第 14 节、`styles-sidebar-toolbar.css` 的选择器项）。
- 进度只保留**按钮内联**（`SearchQueryPanel` 的 `searchProgressLabel`）+ 工具栏摘要文案（`toolbarMetaLabel`：`检索中 · 00:12`）。

## 2. 检索内容与输入不一致 —— phrase 模式被逗号拆词

**现象**：输入一整条含逗号的 SQL 片段（`... insert into per_emp_info (BUSINESS_ID, USER_ID, NAME, DEPTID, ...`），
结果里 `'男'`、`'本科'`、`'李春芝'` 等**碎片**被下划线高亮，像是「检索的不是我输入的」。

**根因**：`parseKeywordTerms`（`utils.ts`）无条件按 `\n` 和 `,，` 拆词。默认的 phrase（精确包含）模式下，
服务端只取 `normalizedTerms[0]`（第一个逗号前的片段）做匹配，前端又拿整串所有碎片去高亮——
输入一条 SQL，检索的是它的第一段，高亮的却是散落各处的子串。三个调用点（`App.tsx` 高亮、`useLogViewer.ts` 检索词）都受影响。

**调整**：
- 新增 `resolveSearchTerms(input, mode)`：**phrase 模式整句成词（不拆逗号）**，any/all 才拆多词。
- `App.tsx` 高亮、`useLogViewer.ts` 的 `runSearch`（含 primaryKeyword、多文件分支）统一改用它。
- 排除词仍走 `parseKeywordTerms`（排除场景本就按多词理解）。

## 3. 检索太慢 —— 全文扫描用 awk 逐行解释

**现象**：几百 MB 的 `catalina.out` 全文扫描要等很久。

**根因**：`buildStreamingSearchCommand` 的全文扫描阶段用 **awk 逐行 `index()`/`~`** 匹配，
等于让脚本解释器扫完整个文件（O(文件行数)）。而「首批快搜」阶段用的 grep 是 C 层优化（Boyer-Moore/DFA），
快一个数量级以上——但全文扫描完全没用上。

**调整**：新增 grep 快路径 `buildGrepScanCommand` + `GREP_ASSEMBLER_AWK`：
- `grep -a -b -n --line-buffered [-C ctx] -e ... | awk` 组装协议；
- grep 负责匹配（C 层），awk 只对**命中行 + 上下文**做协议组装，复杂度降到 O(命中数)；
- 用 `-b` 字节偏移还原进度上报（`__PROGRESS__`），协议与消费端完全一致。

**回落条件**（`canUseGrepFastScan`）：时间范围 / 排除词 / all 多词 → 仍用 awk（这些需解析或二次过滤，grep 单次扫描无法表达）。
已用 5 个用例 + 端到端执行验证：命中数、上下文行数、无命中时的 PROGRESS 均正确。

## 4. 结果区左侧大片空白 —— 行号列替代时间戳列

**现象**：结果区每行左侧留出约 170px 空白（原为时间戳列），检索结果行没有时间戳，白占一列。

**根因**：`VirtualLogViewer` 对**无时间戳行**统一套用 `.log-line-no-time`，
CSS 固定 `padding-left: 170px`（`--log-time-col-w 148px + gap 12px + 10px`）来对齐时间列。
结果行的格式是 `行号 | 内容`，本就没有时间戳，却继承了这 170px 缩进。

**调整**：
- `VirtualLogViewer` 新增 `variant: "log" | "results"`：
  - `log`（文件预览）：保持时间戳列 + 续行缩进；
  - `results`（结果页签/主结果）：解析 `N | ` 前缀，渲染**行号列**（右对齐 muted）+ 内容列。
- `App.tsx` 传 `variant={activeViewerTabId === "file" ? "log" : "results"}`。
- `theme-modern-v2.css` 新增 `.log-line-results` / `.log-line-num`（行号列约 64px + 间距），
  呼应原型 `.ll` 的「固定 meta 列 + 内容列」语言，同时保留 `Cmd/Ctrl 点击跳转原日志` 的定位锚。
- 选区字符偏移映射同步按 variant 走（`getLineMetaPrefixLength`），复制/选行不受拆列影响。
