# 运行维护

## 1. 本地启动

仓库根目录：

```bash
cd /Users/lyc/Git/GitHub/server-log-console
```

安装依赖：

```bash
npm install
```

## 2. SSH 凭证配置

方式一：统一账号密码

```bash
export SERVER_LOG_SSH_USERNAME=root
export SERVER_LOG_SSH_PASSWORD='your-password'
```

方式二：按服务器分别维护

```bash
export SERVER_LOG_CREDENTIALS_JSON='{
  "demo-travel-116": {"username":"root","password":"your-password"},
  "finalshell:abc123": {"username":"root","password":"your-password"}
}'
```

如果已经从 FinalShell 成功导入并解密到可用密码，也可以直接在界面里补录并保存，刷新页面后仍会保留。

## 3. 启动本地连接服务

```bash
npm run dev:gateway
```

启动后默认提供：

- HTTP：`http://localhost:4040`
- WebSocket：`ws://localhost:4040/ws/live`

## 4. 启动前端

开发模式：

```bash
npm run dev:extension
```

构建模式：

```bash
npm --workspace @server-log-console/extension run build
```

## 5. FinalShell 导入规则

本地连接服务会优先读取手动指定目录，其次自动尝试常见安装位置。

当前支持：

- macOS：`~/Library/FinalShell/conn`
- Linux：`~/.finalshell/conn`、`~/FinalShell/conn`
- Windows：`%LOCALAPPDATA%/FinalShell/conn`、`%APPDATA%/FinalShell/conn`

当前策略：

- “生产”分组会正常导入和展示
- 系统不会擅自替用户发起连接
- 是否连接、读取、搜索，由用户在界面中触发

## 6. 常见问题

### 6.1 提示没有可用凭证

检查以下来源：

- `SERVER_LOG_CREDENTIALS_JSON`
- `SERVER_LOG_SSH_PASSWORD`
- `SERVER_LOG_SSH_PRIVATE_KEY`
- 当前服务器是否已在界面里保存用户名、密码或私钥

### 6.2 实时日志连上了但没有内容

检查：

- 目标文件路径是否真实存在
- 当前 SSH 用户是否有读取权限
- 目标机器是否支持 `tail -F`

### 6.3 导入后看不到服务器

检查：

- FinalShell 目录是否正确
- 对应连接文件是否真的存在于 `conn` 下
- 本地是否保存了错误的手动路径

### 6.4 大日志搜索慢或超时

这是大文件远程检索的正常风险，建议优先：

- 先选时间范围再搜关键字
- 用多关键字缩小范围
- 先看尾部切片再决定是否全量搜索
- 直接复制系统生成的搜索命令，到服务器终端执行二次排查

## 7. 推荐验收路径

1. 导入 FinalShell 连接
2. 选择测试或开发服务器
3. 自动连接并展开日志目录
4. 选择一个日志文件，确认尾部自动打开
5. 搜索已知关键字
6. 启动实时日志
7. 下载结果或片段

## 8. 运维建议

- 本地连接服务仅部署在个人本机，不建议暴露到公网
- 浏览器插件与本地网页都依赖本机本地连接服务，升级时保持两者版本一致
- 对于 1GB 以上日志，优先使用时间范围、尾部切片和多关键字组合检索
- 若命令行比界面更高效，优先复制系统生成的搜索命令去服务器执行
