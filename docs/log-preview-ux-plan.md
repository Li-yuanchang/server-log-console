# 日志预览与检索完整方案

更新时间：`2026-07-01`

## 1. 背景

日志预览当前承载了文件尾部阅读、搜索结果页、命中跳转、实时 tail、切片翻阅、复制、PiP 小窗等多种职责。功能已经可用，但体验上仍存在“跳动、迷路、打断阅读、复制不稳”的问题。

这份文档不是局部优化清单，而是日志预览与检索的完整产品方案。目标是统一：

- 用户如何进入日志
- 如何检索
- 如何看结果
- 如何跳转定位
- 如何继续阅读
- 如何退出和返回

## 2. 体验目标

- 普通滚动必须像正常阅读器，不应在用户没明确确认时切换到另一段内容。
- 搜索命中跳转后必须让用户知道“从哪里来、跳到哪里、怎么回去”。
- 实时 tail 只在用户明确处于跟随状态时自动到底部，用户手动上翻后不得抢滚动位置。
- 复制长内容不能依赖虚拟列表可视 DOM，必须提供稳定的按行范围复制能力。
- 文件切片、搜索结果、实时跟随三类状态要在 UI 上明确区分，避免用户靠猜。

## 3. 产品主流程

### 3.1 进入日志

1. 用户在文件目录里点开日志文件
2. 默认打开文件尾部或最近片段
3. 如果是 `.log/.out`，默认显示“实时日志”状态，但不强制一直抢滚动
4. 顶部固定显示当前文件、模式、位置和状态

### 3.2 发起检索

1. 用户在搜索栏输入关键字
2. 回车后进入检索流程
3. 检索阶段只显示稳定的阶段条，不把多个数值同时铺在主视图上
4. 结果出来后，默认保留当前阅读位置，不自动打断用户视线

### 3.3 查看结果

1. 结果页默认呈现“结构化结果”，不是一大段粗文本
2. 用户可以点结果进入日志上下文
3. 结果页和日志预览页通过明确的定位条互相返回

### 3.4 回到阅读

1. 用户回到日志上下文后，看见来源结果、文件、行号
2. 可以一键返回结果页
3. 可以继续滚动、继续筛选、继续复制

### 3.5 退出或切换

1. 切换服务器或文件夹时保留可恢复状态
2. workspace 恢复时优先恢复上次阅读模式和结果页
3. 避免把用户正在看的内容清空成大白板

## 4. P0 优先项

### 3.1 滚轮切片策略

现状：

- `handleViewerWheel` 在滚动到当前切片边缘时直接触发 `navigateSlice("prev" | "next")`。
- 大日志阅读体感像“翻页跳走”，用户还没读完当前页就可能进入下一段。

调整方向：

- 普通滚轮只滚当前可见内容。
- 到达当前切片顶部/底部时显示轻量边缘提示，例如“已到当前片段底部，继续加载下一段”。
- 只有二次确认动作才切片：点击提示、按 PageDown/PageUp、或在边缘继续滚动超过阈值。
- 切片完成后保持稳定锚点：上一段落底部，下一段落顶部。

涉及入口：

- `apps/extension/src/ui/useLogViewer.ts`
- `apps/extension/src/ui/VirtualLogViewer.tsx`
- `apps/extension/src/ui/App.tsx`

### 3.2 回到底部语义

现状：

- 多处通过 `scrollToBottom()`、定时器重试和 UI 滚动位置判断实现。
- 特殊比例、实时刷新、搜索上下文切换时容易出现回不到底部或抖动。

调整方向：

- “回到底部”统一解释为：读取文件尾部切片，然后定位最后一行。
- 如果实时跟随已暂停，回到底部后恢复跟随。
- 如果当前不是文件预览，而是搜索结果页，则回到底部只作用于当前结果页滚动，不触发文件尾部读取。
- 删除依赖右侧百分比推算尾部的路径。

涉及入口：

- `apps/extension/src/ui/useLogViewer.ts`
- `apps/extension/src/ui/useLiveFollow.ts`
- `apps/extension/src/ui/VirtualLogViewer.tsx`

### 3.3 搜索命中跳转上下文

现状：

- 点击搜索命中会切到文件预览和行上下文，但用户容易不知道当前定位来自哪个结果。

调整方向：

- 跳转后展示固定定位条：来源结果、文件名、目标行号、返回结果按钮。
- 当前命中行使用稳定高亮，不使用缩放或几何变化。
- 保留跳转前结果页滚动位置，返回结果时恢复。

涉及入口：

- `apps/extension/src/ui/useLogViewer.ts`
- `apps/extension/src/ui/App.tsx`
- `apps/extension/src/styles-viewer-search.css`

### 3.4 长文本复制

现状：

- 复制依赖浏览器 Selection 和虚拟列表已渲染 DOM，长距离拖选仍可能不稳定。

调整方向：

- 增加按行范围复制：点击行号/书签区设置起点和终点，复制完整行文本。
- 普通拖选保留，用于短文本复制。
- 复制菜单位置绑定 viewer 容器，禁止飘到左上角或脱离终端/日志区域。

涉及入口：

- `apps/extension/src/ui/VirtualLogViewer.tsx`
- `apps/extension/src/ui/useLogViewer.ts`
- `apps/extension/src/styles-viewer-search.css`

## 5. P1 优化项

- 日志预览顶部固定信息区：当前文件、当前模式、当前定位、实时状态。
- 结果 tab 名称从“结果 N”升级为“关键词 · 文件名”。
- 右侧 rail 区分文件位置 rail 和搜索结果概览 rail，视觉和文案不能混用。
- 搜索结果页改成结果列表表达：行号、时间、级别、上下文、点击区域。
- 结果页支持筛选、排序、折叠上下文和回看最近命中。
- 快捷键帮助入口：`Cmd/Ctrl+F`、`n/Shift+n`、`Cmd/Ctrl+End`、`PageUp/PageDown`。

## 6. P2 打磨项

- 错误/告警高亮增加图例。
- 文件 offset 等工程信息默认收起，只在更多工具中展示。
- PiP 小窗只保留阅读必要动作，减少按钮密度。
- loading 按 `docs/loading-feedback-spec.md` 收口，禁止新增独立风格。
- 搜索结果统计只保留阶段级数值，不保留每次刷新都跳动的细颗粒数字。

## 7. 搜索方案

### 7.1 检索策略

- 默认是后台检索，不阻塞阅读器主线程
- 长日志默认采用分阶段扫描
- 先给阶段反馈，再给结果反馈，避免大量细碎数值变化
- 结果数量、命中数、扫描字节数只在阶段变化或结果稳定时更新

### 7.2 搜索展示

- 顶部搜索输入区只显示当前关键字和一个稳定的进度摘要
- 中间区域展示结构化结果列表
- 结果列表默认按命中行排序，文件名和来源要可见
- 每条结果应包含：
  - 文件名
  - 行号
  - 命中预览
  - 是否来自实时日志/文件片段/全量检索

### 7.3 动态数值策略

- `1/75` 这类阶段数值只在阶段切换时更新
- `22s` 这类耗时只在节流后更新
- `5.1%` / `101MB / 1.9GB` 这类进度只显示一套主数值
- 不允许同一区域同时出现多套不同口径的数值

### 7.4 可借鉴开源方案

- `lnav`：弱化实时数值，强调索引状态和结果浏览
- `klogg`：结果概览更偏列表和导航，不把搜索过程压在正文上
- `ripgrep`：搜索结果本身快速，但 UI 不应该模仿 CLI 的所有输出

## 8. 检索后展示方案

### 8.1 结果页

- 结果页是“可浏览列表”，不是“搜索命令输出”
- 每条结果行应可点击进入日志上下文
- 结果页支持二次筛选，但二次筛选不应改变当前阅读位置

### 8.2 日志上下文页

- 日志上下文页要突出来源结果和返回入口
- 顶部条只保留稳定信息，不重复展示整段路径
- 当前命中行高亮要稳定，不做缩放、不做抖动

### 8.3 实时尾部

- 实时 tail 是阅读模式之一，不是另一个独立产品
- 用户手动上翻时暂停跟随
- 回到底部后再决定是否恢复跟随

## 9. 验证要求

- `npm --prefix apps/extension run build`
- 大日志打开后默认尾部稳定显示。
- 搜索结果点击跳转后能看清来源和目标行。
- 手动上翻实时日志后，新日志到达不抢滚动。
- 回到底部可稳定恢复到最后一行。
- 长距离复制不截断。

## 10. 执行记录

- 已调整滚轮切片策略：滚到片段边缘时先提示，短时间连续第二次同向滚动才加载上一段/下一段，避免普通阅读被自动翻段打断。
- 已调整尾部定位入口：回到底部、工具栏“尾”、`Cmd/Ctrl+End`、实时重连统一走强制尾部读取，避免复用旧尾部缓存导致回不到最新日志。
- 已增加搜索定位条：从搜索结果跳到日志上下文后显示来源结果、文件、目标行，并提供“返回结果”按钮恢复到原结果页位置。
- 已增加按行范围复制：文件预览中 Cmd/Ctrl 点击日志行设置起点/终点，复制时直接从完整行数据取文本，不依赖虚拟列表已渲染 DOM。
- 已升级日志预览顶部信息区：固定展示当前模式、标题、来源、位置和运行状态，替代原来三个裸文本 meta，降低用户迷路概率。
