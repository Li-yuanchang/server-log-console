# 本地应用与插件安装

## 1. 形态说明

当前产品同时支持两种使用形态：

- 本地网页工作台：适合日常主用，窗口更大，调试更方便
- Chrome 插件：适合固定在浏览器侧边使用，便于快速打开

这两种形态共用同一套本地连接服务，所以都需要先启动本地服务。

## 2. 本地网页模式

启动：

```bash
cd /Users/lyc/Git/GitHub/server-log-console
npm run dev:gateway
npm run dev:extension
```

访问地址：

- `http://127.0.0.1:4173/`
- `http://localhost:5174/`

适合场景：

- 长时间排日志
- 大屏幕查看目录树与搜索结果
- 联调接口、验证实时日志和下载功能

## 3. Chrome 插件模式

### 3.1 先构建扩展

```bash
cd /Users/lyc/Git/GitHub/server-log-console
npm --workspace @server-log-console/extension run build
```

构建输出目录：

`/Users/lyc/Git/GitHub/server-log-console/apps/extension/dist`

### 3.2 在 Chrome 中加载

1. 打开 `chrome://extensions/`
2. 打开右上角“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择目录 `/Users/lyc/Git/GitHub/server-log-console/apps/extension/dist`

### 3.3 插件依赖的本地服务

插件本身不直接 SSH 到服务器，而是访问本机本地连接服务：

- HTTP：`http://localhost:4040`
- WebSocket：`ws://localhost:4040/ws/live`

因此使用插件前，必须先启动：

```bash
npm run dev:gateway
```

如果插件打开后没有服务器、没有实时日志或无法搜索，优先检查本地连接服务是否已启动。

## 4. 插件权限与设置

当前插件权限：

- `storage`：保存本地界面状态
- `downloads`：下载日志结果和实时片段
- `host_permissions`：访问本机本地连接服务 HTTP / WebSocket

当前清单已允许：

- `http://localhost:4040/*`
- `ws://localhost:4040/*`

如果后续要改成本机其他端口，需要同步修改：

- `apps/extension/manifest.json`
- 前端中的 `localServiceBase`
- WebSocket 地址

## 5. 用户如何设置 FinalShell

不要假设每台机器的 FinalShell 路径一致，界面里应让用户可见并可修改。

推荐流程：

1. 打开设置
2. 查看系统自动识别到的 FinalShell 路径
3. 如果识别不对，再手动填写 `conn` 目录
4. 保存后重新导入服务器清单

常见目录：

- macOS：`~/Library/FinalShell/conn`
- Windows：`%LOCALAPPDATA%/FinalShell/conn`
- Linux：`~/.finalshell/conn`

## 6. 本地化要求

本产品默认面向中文使用者，当前约束如下：

- 主界面文案使用中文
- 产品文档使用中文
- 常用操作提示、连接状态、错误原因使用中文
- 允许保留必要的英文技术词，如 `FinalShell`、`Chrome`、`WebSocket`
