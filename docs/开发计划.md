# 开发计划

## 1. 当前阶段判断

项目当前处于"主链路完成，产品体验收口与结构治理并行"的阶段。

截至 `2026-04-08`，整体完成度按当前范围估算约为 `82%`。已经做完的重点不是静态原型，而是能真实连接服务器、打开目录、读取日志、历史检索、看实时、下载片段，并支持从搜索结果回跳日志上下文、实时断线自动重连、堡垒机二跳基础接入的可运行工作台；但 UI 工具化、大日志阅读器体验、插件交付、自动化测试和代码结构治理还没有完全收尾。

同时，代码结构拆分已作为独立专项启动，当前完成约 `52%`，终端链路已完成第一轮拆层，但前端 `App.tsx`（3711 行）和网关 `ssh-executor.service.ts`（965 行）仍然偏重，后续需要继续推进。

## 3. 阶段拆分

### P1：基础工程

目标：

- 建立 monorepo
- 完成 shared 类型
- 完成网关和前端基础入口

状态：已完成

### P2：连接导入与连接管理

目标：

- 自动导入 FinalShell
- 支持手动指定目录
- 支持凭证状态查看
- 支持手动补录与本地保存

状态：已完成主链路，已补堡垒机二跳基础版

### P3：真实执行能力

目标：

- 通过 SSH 在远程服务器执行历史搜索
- 读取目录与日志文件
- 返回实时日志流

状态：已完成主链路

说明：

- 搜索主链路已优先采用 `awk`、`grep`、`tail`
- 目录浏览、目录检测、元信息、切片读取也已切换到 shell 工具链
- 当前该阶段重点已从“去 Python 化”转为“继续增强大日志阅读体验与稳定性”

### P4：日志工作台能力

目标：

- 历史搜索
- 实时日志
- 多关键字与正则
- 结果下载
- 大日志切片
- 目录浏览

状态：已完成基础版，已补实时断线重连；其中历史搜索约 89%，大日志切片约 80%，实时日志约 55%

### P5：真实环境验证

目标：

- 非生产环境真机验证
- 浏览器运行态检查
- 核心链路截图留档

状态：已完成基础验证

### P6：FinalShell 风格收口

目标：

- 单屏工具化布局
- 降低网页表单感
- 提升目录树、目录内容区、日志窗口的一致性
- 收紧高级查询区和顶部工具条

状态：进行中，约 80%

已完成：

- 全局按钮圆角统一 8px -> 3px，更工具化
- 工具栏标签页紧凑化（高度、内边距、激活态加粗）
- 高级查询区间距收紧（gap 3->2, padding-top 2->1）
- 输入框降低表单感（高度 25->23, 边框柔化）
- 面板间距一致化（shell gap 2->1, sidebar gap 2->1）
- 侧栏服务器条目紧凑化（min-height 34->30, padding 收紧）
- 状态栏收紧（padding、gap 减小）

### P7：日志阅读体验增强

目标：

- 更自然的翻页
- 更强的快捷键
- 更清晰的当前位置和片段定位
- 更接近大日志阅读器的工作流

状态：进行中，快捷键约 85%，切片阅读约 90%，实时日志约 80%

切片阅读器已完成：

- Ctrl+Home / Ctrl+End 快捷键：跳到文件头/尾
- 可调切片大小：32KB / 64KB / 128KB / 256KB 四档可选
- 位置百分比显示：状态栏显示当前位置占比

实时日志已完成：

- 关键字透传：前端将搜索关键字传给 WebSocket，后端 tail -F | grep 过滤

- 清空内容：实时模式下增加清空按钮
- 行数统计：状态栏显示已接收行数和连接状态
- 导出内容：复用 downloadTextFile 导出实时日志内容

## 4. 近期任务排序

### 第一优先级

- 继续收 UI，重点是顶部工具条、查询区、目录树和日志窗口
- 统一视觉节奏，减少页面割裂感
- 继续真实验证打开目录、打开日志、实时日志、切片翻页

### 第二优先级

- 增强大日志阅读器能力
- 评估切片定位、命中跳转、滚轮翻页
- 评估日志格式自动识别与时间筛选适配

### 第三优先级

- 收插件安装与说明文档
- 继续补异常路径与兼容性说明
- 固化自动化验证脚本与执行说明

### 结构拆分（与功能开发并行，按节奏穿插推进）

- 继续拆前端 `App.tsx`（查询工具条、文件工作区、搜索结果区、连接设置区）
- 继续拆网关 `index.ts`（live websocket、HTTP route handlers、service 装配工厂）

- 每轮拆分后执行 `npm run typecheck` 和 `npm run build` 回归

## 5. 关键风险

- UI 打磨量仍然较大，返工概率高
- 用户对工具化体验要求高，不能只满足“功能能点通”
- 大日志能力虽然已可用，但距离成熟阅读器仍有明显差距
- FinalShell 凭证自动提取可能受版本和加密实现影响，尤其私钥场景仍需真实样本验证，不能把它当成唯一方案
- 自动化测试不足，当前仍偏依赖人工验证
- 前端 `App.tsx` 3711 行、网关 `ssh-executor.service.ts` 965 行，巨石文件增加维护和并行开发风险
- 结构拆分与功能开发并行，节奏控制不好可能互相干扰，导致两边都慢
