# 当前系统梳理与排查计划

更新时间：`2026-06-29`

## 1. 本轮结论

当前系统是“本地 gateway + React 工作台 + Electron 壳”的组合。近期 bug 多数不是单点函数错误，而是系统拆分后产生的状态边界漂移：

- 前端 UI 已拆出大量组件和 hooks，但 `App.tsx` 仍是跨域编排中枢
- gateway 的模块服务已拆出，但 `index.ts` 仍聚合 HTTP 路由、WebSocket、录制、静态托管和启动逻辑
- shared 类型已经覆盖主要协议，但部分前端 API 返回仍使用局部类型或 `Record<string, unknown>`
- 样式已从单文件拆成多个 `styles-*` 文件，但 `theme-modern.css` 仍是最强覆盖层
- Electron、浏览器、Chrome 扩展三个宿主共用前端，但可用能力和样式约束不同

当前状态总览：

| 分类 | 状态 | 说明 |
|---|---|---|
| 主体拆分 | 已完成 | 前端组件 / hooks、gateway service、基础样式文件、Electron 打包链路已形成独立边界 |
| 功能接线 | 已完成主链路 | 文件浏览、搜索、终端、工具区、设置、PIP / Electron 主链路已接回 |
| 文档口径 | 已对齐 | 当前文档明确区分“已完成拆分”和“后续复杂度治理” |
| 回归验证 | 待继续 | 最近集中修过 UI、搜索、终端、JumpServer、Electron 资源，仍建议按矩阵做一轮实态验证 |
| 长期治理 | 待触发 | 仅在后续触达相关模块时处理，不主动为拆而拆 |

旧版系统梳理已归档到 `docs/archive/当前系统梳理与排查计划-2026-05-06.md`。

## 4. 当前主链路

### 4.1 启动链路

Electron：

1. `apps/electron/main.cjs`
2. 加载 extension dist
3. 启动或导入 gateway
4. 前端 health check
5. 前端拉服务器列表和导入配置

开发模式：

1. `npm --prefix apps/gateway run dev`
2. `npm --prefix apps/extension run dev`
3. extension 通过 `http://localhost:4040` 调 gateway

注意：根目录没有完整 dev 脚本，不要沿用旧文档的根脚本命令。

### 4.2 服务器选择链路

1. `SidebarPanel` 触发选择
2. `useServerManagement.selectServerById`
3. `useWorkspaceSessionManager` 保存/恢复 workspace 状态
4. `serverId` 变化触发凭证、路由、文件浏览、终端/live 状态收口
5. `useServerConnection` 拉凭证、路由、执行连接测试

优先排查：

- `useServerManagement.ts`
- `useWorkspaceSessionManager.ts`
- `useServerConnection.ts`
- `App.tsx` 中 serverId 相关 effect

### 4.3 文件打开链路

1. 连接测试或路径栏触发目录读取
2. `useLogViewer.fetchDirectoryListing`
3. `FileBrowserGrid` 展示目录树和内容
4. 文件点击进入 `openEntry`
5. `apiGetLogMeta`
6. `apiGetLogSlice`
7. `VirtualLogViewer` 渲染内容

优先排查：

- `useLogViewer.ts`
- `FileBrowserGrid.tsx`
- `VirtualLogViewer.tsx`
- gateway `file-browser.service.ts`
- gateway `log-slice.service.ts`

### 4.4 搜索链路

1. `SearchQueryPanel` 收集条件
2. `useLogViewer.runSearch`
3. 单文件走 `apiCreateSearchTask`
4. 多文件走 `apiMultiFileSearch`
5. 单文件任务轮询 `apiPollSearchTask`
6. 结果写入 `results` 和 `resultTabs`
7. viewer 切到日志预览或保留文件目录
8. 点击命中走行上下文或切片定位

优先排查：

- `useLogViewer.ts`
- `SearchProgressPanel.tsx`
- `VirtualLogViewer.tsx`
- gateway `log-search-task.service.ts`
- gateway `multi-file-search.service.ts`
- gateway `command-builder.ts`

### 4.5 终端链路

1. `openTerminalView`
2. `ensureTerminalSessionId`
3. `useTerminalSession`
4. `WS /ws/terminal`
5. gateway `terminal-websocket.ts`
6. `ssh-executor.service.ts` 建立 shell
7. xterm 渲染输出并处理 resize/input

优先排查：

- `TerminalWorkspace.tsx`
- `useTerminalSession.ts`
- `useTerminalWindowManager.ts`
- gateway `terminal-websocket.ts`
- gateway `terminal-session-manager.ts`

### 4.6 Electron 打包链路

1. `npm --prefix apps/electron run release:mac`
2. `predist:mac`
3. `bump-version.cjs`
4. `prepare-gateway.cjs`
5. `electron-builder --mac`
6. `install-mac-app.cjs`

优先排查：

- `apps/electron/package.json`
- `apps/electron/prepare-gateway.cjs`
- `apps/electron/main.cjs`
- extension dist 中 CSS/JS 是否已更新
- `/Applications/日志控制台.app/Contents/Resources`

## 5. 当前高风险问题清单

### P0：打包后主功能不可点击

常见原因：

- Electron drag region 覆盖按钮
- CSS 构建产物未更新
- 旧 app 未完全替换
- toolbar 上层透明元素吃掉点击

检查入口：

- `styles-sidebar-toolbar.css`
- `theme-modern.css`
- `apps/electron/main.cjs`
- DevTools Elements 的 `-webkit-app-region`

### P0：日志预览和文件目录切换异常

常见原因：

- `activeLogView` 和 `activeViewerTabId` 不一致
- `results` 被 server/workspace 切换副作用清空
- `resultTabs` 和当前文件路径重复表达导致 UI 判断错位
- 点击命中没有明确选中目标

检查入口：

- `useLogViewer.ts`
- `App.tsx`
- `VirtualLogViewer.tsx`
- `SearchToolbarActions.tsx`

### P0：大文件底部/进度条定位异常

常见原因：

- 用百分比反推 offset 时遇到边界值
- `sliceData.nextOffset`、`fileSize`、`actualOffset` 混用
- 日志预览模式和文件目录模式共用了 reader rail 状态
- “回到底部”没有强制走尾部读取

检查入口：

- `useLogViewer.ts`
- `useLiveFollow.ts`
- `VirtualLogViewer.tsx`
- `log-slice.service.ts`

### P1：终端不像正规终端

常见原因：

- xterm viewport 没跟随到底部
- 输出后 fit/resize 时机不对
- 复制粘贴浮层基于页面定位而不是终端容器定位
- detached/embedded 两种模式共享状态不完整

检查入口：

- `useTerminalSession.ts`
- `TerminalWorkspace.tsx`
- `styles-terminal-workspace.css`
- `styles-pip-toast.css`

### P1：样式看起来跳动或变重

常见原因：

- 初始样式和 `theme-modern` 覆盖后样式不同
- Electron class 延迟挂载导致二次布局
- `styles-responsive.css` 后置覆盖了常规样式
- loading/toast 用色和动画过重

检查入口：

- `docs/style-architecture.md`
- `theme-modern.css`
- `styles-responsive.css`
- `styles-pip-toast.css`
- `useElectronEnv.ts`

## 6. 排查执行顺序

每个 bug 按下面顺序处理，不要先改表层样式或局部状态：

1. 复现并确认宿主：Electron / 浏览器 / Chrome 扩展
2. 确认当前视图模式：文件目录 / 日志预览 / 实时 / terminal / utility
3. 找前端状态入口：`App.tsx` + 对应 hook
4. 找 API 或 WebSocket 入口：`api.ts` + gateway route
5. 找共享类型：`packages/shared/src/index.ts`
6. 找样式覆盖链：基础 `styles-*` -> `theme-modern.css` -> Electron/PiP 特例
7. 修复后同时做源码构建和目标宿主验证

## 7. 推荐验证矩阵

| 改动类型 | 最低验证 | 额外验证 |
|---|---|---|
| 纯前端状态 | `npm --prefix apps/extension run build` | 浏览器手测主链路 |
| 样式 | `npm --prefix apps/extension run build` | 浏览器截图 + Electron 打包后检查 |
| gateway API | `npm --prefix apps/gateway run build` | 调接口或通过 UI 跑链路 |
| shared 类型 | extension build + gateway build | 检查前后端字段消费 |
| Electron | `npm --prefix apps/electron run release:mac` | 安装后 DevTools 检查资源版本 |

## 8. 后续治理项

功能拆分主体已经完成：前端组件 / hooks、gateway service、样式基础文件、Electron 打包链路都已经形成独立边界。

以下不是当前必须执行的遗留任务，而是“后续触达对应模块时再顺手治理”的低优先级复杂度项：

1. gateway `index.ts` 可在新增路由或 WebSocket 能力时再拆成 routes/ws/bootstrap
2. `useLogViewer.ts` 可在继续改搜索、切片、目录逻辑时再按职责细化
3. `theme-modern.css` 可在大范围主题改造时再按域拆分，避免单独拆 CSS 引入覆盖顺序风险
4. `api.ts` 中局部返回类型可在接口契约变更时补到 shared，减少字段漂移

- README 已补齐 extension、gateway、Electron 开发启动和 macOS 打包安装命令。
