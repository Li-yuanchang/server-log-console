# 架构设计

## 1. 总体架构

项目采用“浏览器扩展 + 本地网关”的双层结构：

- 浏览器扩展负责界面交互、参数录入、结果展示、文件下载
- 本地网关负责读取 FinalShell、维护服务器清单、拼装检索命令、建立 SSH 连接、转发实时日志流

这样拆分的核心原因是浏览器不适合直接处理 SSH 与 shell 命令，而本地网关更适合承接凭据、策略和执行控制。

## 2. 分层说明

### 2.1 浏览器扩展层

职责：

- 展示服务器列表与当前环境信息
- 接收日志路径、日期、关键字等结构化输入
- 调用 HTTP API 发起历史检索、目录浏览、元信息读取和切片读取
- 建立 WebSocket 连接查看实时日志
- 将检索结果或实时片段下载到本地

该层不直接接触 SSH，也不直接拼接远程 shell 指令。

### 2.2 本地网关层

职责：

- 读取内置服务器配置与 FinalShell 导入结果
- 在多平台下自动发现 FinalShell 配置目录
- 统一解析 SSH 凭据
- 构建相对安全的日志查询命令
- 浏览远程日志目录
- 执行历史日志检索
- 提供大日志元信息与切片能力
- 管理实时日志 WebSocket 会话
- 对生产分组连接增加谨慎标记，但是否执行由用户显式触发

本地网关是整个产品的执行核心。

### 2.3 共享类型层

职责：

- 统一定义前后端请求与响应结构
- 保证浏览器扩展和本地网关字段含义一致
- 降低联调时字段偏差带来的成本

## 3. 关键运行流程

## 3.1 FinalShell 导入流程

1. 浏览器扩展调用 `GET /api/import/finalshell`
2. 网关根据当前系统平台拼装候选目录，或者优先读取 `FINALSHELL_HOME`
3. 网关读取 FinalShell 目录中的分组和连接配置
4. 转换为统一的 `ServerSummary` 结构
5. 为分组路径中包含“生产”的连接增加谨慎提示
6. 将服务器注册到内存中的服务清单
7. 返回导入结果、导入时间和实际解析到的目录

## 3.2 历史日志检索流程

1. 用户在扩展中选择服务器、日志文件、日期和关键字
2. 扩展调用 `POST /api/logs/search`
3. 网关根据 `serverId` 查找目标服务器
4. 网关解析该服务器对应的 SSH 凭据
5. 网关根据查询条件生成日志检索命令
6. 通过 SSH 到远端 Linux 服务器执行命令
7. 返回原始输出与结构化匹配结果

## 3.3 远程目录浏览流程

1. 扩展提交目录路径到 `POST /api/logs/files`
2. 网关通过 SSH 执行目录读取命令
3. 返回目录项名称、路径、类型和大小
4. 用户点击文件后自动回填检索路径

## 3.4 大日志切片流程

1. 扩展调用 `POST /api/logs/meta` 获取文件大小、修改时间、编码提示
2. 用户设置偏移量和切片长度
3. 扩展调用 `POST /api/logs/slice`
4. 网关按字节区间读取远程文件内容
5. 为了提高可读性，网关尽量把返回内容裁切到完整行边界
6. 扩展根据 `nextOffset` 支持继续向后翻阅

这套流程的目标是让几个 G 的日志文件也能以可控成本浏览，而不是一次性整文件拉回本地。

## 3.5 实时日志流程

1. 扩展建立 `WS /ws/live` WebSocket 连接
2. 扩展发送 `start` 指令，带上服务器、文件路径和关键字
3. 网关解析目标服务器与凭据
4. 网关通过 SSH 执行 `tail -F`，必要时追加过滤能力
5. 网关把 stdout 和 stderr 按块转发给浏览器
6. 浏览器持续更新实时日志面板，并允许用户手动停止和下载当前片段

## 4. 状态管理

当前版本的状态主要保存在内存中，包括：

- 导入后的服务器列表
- 当前 WebSocket 实时会话
- 本次运行期间的服务注册表

优点是部署简单、启动快、依赖少。缺点是重启后导入状态会丢失，需要重新导入 FinalShell 连接。

## 5. 安全设计要点

### 5.1 SSH 能力集中在网关

浏览器扩展不负责 SSH 协议与命令执行，能降低凭据暴露面，也方便统一治理。

### 5.2 结构化检索请求

前端只提交结构化字段，不直接提交自由 shell 脚本，能降低命令注入风险，并为后续做日志模板化搜索留出空间。

### 5.3 生产分组谨慎策略

“生产”分组不再被系统硬性屏蔽，而是作为提醒信息展示。系统不主动自动连接，只有用户显式发起检索、浏览或实时追踪时才执行。

## 6. 多平台兼容策略

FinalShell 配置目录会根据平台自动尝试以下位置：

- macOS：`~/Library/FinalShell/conn`
- Linux：`~/.finalshell/conn`、`~/FinalShell/conn`
- Windows：`%LOCALAPPDATA%/FinalShell/conn`、`%APPDATA%/FinalShell/conn`、`%USERPROFILE%/FinalShell/conn`

如果用户自行调整了 FinalShell 安装目录，可通过 `FINALSHELL_HOME` 显式覆盖。

## 7. 为什么不直接做成纯插件

如果只有浏览器插件，没有本地网关，会遇到以下问题：

- 浏览器环境无法直接建立标准 SSH 连接
- 命令执行、目录读取、流式 tail 都会非常受限
- 凭据管理很难做得安全
- 无法稳定处理实时日志流与大文件分段读取

因此当前方案需要本地网关参与，它并不是额外负担，而是产品可用性的基础。

## 8. 未来扩展方向

后续架构可以继续演进到以下方向：

- 为 Tomcat、Spring Boot、Nginx 等日志格式提供专用检索模板
- 将搜索命中位置和大日志切片偏移打通
- 增加搜索历史与收藏方案
- 接入系统钥匙串或企业级密钥管理
- 增加操作审计能力
- 提供团队共享的案例留痕与导出模板

当前这套架构已经足以支撑“快速定位日志问题”的核心场景，后面重点是把体验和治理能力做深。
