1自动切档，无按钮档位
拖左缘手柄或点宽度预设：布局由 @container 按容器宽度自动切换 （<560 移动档 / ≥560 宽档）。实现即用容器查询，JS 不写宽度分支。
2移动档：底部 tab 导航 + app bar
<560px ≈ 手机宽度，直接用最熟的移动范式：日志 / 文件 / 终端三个 tab 沉底， 顶栏变成 app bar（当前屏名 + 全局动作）。当前服务器以 chip 常驻，点击整屏 push 选服层—— 未选服务器时的空态天然就是这一层，不新增导航概念。
3面包屑接管目录层级
⌂ / data / logs 每级可点跳级（组件已有：FileBrowserPathbar browse/edit 双模式）； 末尾「目录」按钮打开底部 sheet（树搬进去，复用 FileBrowserTreeColumn）。 现状是文件树列被 display:none 且无替代。
4文件表按档位裁列
列优先级：名称 > 大小 > 修改时间 > 类型。宽档 名称+大小+时间； 移动档 名称+大小 + 44px 大行距 + 目录行尾 ›。「类型」永久并入图标色/悬浮提示（对齐 S15 <800 规则）。
5宽档（≥560）：桌面压缩形态
侧栏 172px 常驻（完整两行服务器行 + 悬浮快捷操作）+ 树列 132px（可开合）+ 文件表三列。 用户把面板拉宽时自动回到桌面形态，不浪费横向空间。
6底部状态条单行化
点 + 摘要（服务器 · 账号 · 路径，省略）+ 详情；移动档位于 tab 栏上方。任何档位不换行不截碎。
7移动化的边界（刻意不做）
不做：手势导航、独立移动端组件树（fork 会重演 theme-modern/v2 双轨维护—— 移动化只发生在 CSS 档位 + 共享组件参数层）。做：底部 tab、44px 行距、全屏层/sheet 这些纯呈现层的移动范式。

现状问题 → 原型方案对照

现状（side panel 实测）根因本原型方案
服务器行 40px 钉死：名称/主机截成「堡...」「127....」「192...」，服务器之间无法分辨 media ≤1024 桌面档在侧栏恒成立 + theme-modern-v2 display:flex !important 反杀隐藏规则，.server-item{width:40px} 仍生效 移动档整屏选服层（46px 完整行：点 + 名称 + host）；宽档侧栏 172px 完整两行；行内容永不被固定宽度截碎
标题/过滤框/分组/计数消失，只剩两个竖排图标 media ≤1024 对 sidebar-head-title / pane-title-row / pane-section>input / server-group-title 一律 display:none 宽档全部保留（标题并入「服务器」行头）；移动档移入整屏选服层，过滤框/分组/计数完整
文件树列整体消失，目录导航丢失，只有路径输入框 media ≤1024 .browser-tree-column/.browser-resizer{display:none}，规范说「改下拉」但未实现 宽档树列 132px 可开合；移动档面包屑可点跳级 +「目录」底部 sheet（树完整搬进 sheet）
180px 固定侧栏挤爆主区：400px 面板下主区仅 ~216px，文件表不可用 styles-sidepanel.css grid-template-columns:180px 固定列，随面板变窄不降级 移动档侧栏整体退位（单列 + 底部 tab）；宽档（≥560）才用 172px 侧栏，主区始终 ≥380px
首屏骨架与实际布局不一致：骨架画 180px 完整行，挂载后塌成 40px popup.html skeleton 与 theme-modern 档位各画各的 骨架几何跟随容器档位（同一套档位常量），挂载前后零跳变
档位切换不响应屏幕尺寸：桌面断点按窗口求值，侧栏里永远命中窄窗档 @media (max-width:1024px) 在 side panel 恒成立，无法关闭 容器查询分档（本原型同款）：侧栏环境脱离 viewport 媒体查询，拖宽拖窄实时切换
