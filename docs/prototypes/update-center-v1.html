打包与发布流程

评审参考，不进入产品界面；对应发布脚本 scripts/prepare-online-update-release.mjs。
更新源是内网静态目录（网关或 nginx 托管）。发布顺序强制：先传安装包与增量包，最后传清单（latest*.yml / manifest.json），避免客户端拿到清单却 404 安装包。
流水线五步
STEP 1升版electron 版本 +1（predist 自动）；CHANGELOG 补版本条目；扩展 manifest 由构建注入同版本。
STEP 2构建shared → gateway → extension → electron-builder（dmg/zip、nsis/zip、AppImage）。
STEP 3汇总校验release:update 脚本收集产物，校验包内版本一致性，生成 SHA256SUMS 与 manifest.json。
STEP 4上传rsync 到更新主机 desktop-updates/；安装包先传、清单最后传；curl 抽查校验。
STEP 5客户端 OTA启动自动检查或手动检查 → 下载（校验）→ 重启安装 / 扩展与 Web 按各自机制生效。
