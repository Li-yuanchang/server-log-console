# Security Design

## 1. Security Objective

Provide log access convenience without turning the browser extension into a credential store or arbitrary shell runner.

## 2. Current Security Controls

### 2.1 Browser isolation

- The extension calls a local gateway over HTTP and WebSocket.
- The extension does not execute shell commands.
- The extension does not read arbitrary local files directly.

### 2.2 Command control

- The gateway builds commands from structured parameters only.
- Raw user-provided shell commands are not accepted.
- Search values are shell-escaped before command assembly.

### 2.3 Environment boundary

- FinalShell imported entries under `生产` are filtered during import.
- Production FinalShell entries are rejected again during server lookup.

### 2.4 Credential control

- SSH credentials are resolved from environment variables or a mapped JSON object.
- Credentials are not persisted in the extension.
- FinalShell encrypted password fields are not trusted as directly reusable credentials.

## 3. Known Security Gaps

- No audit log is stored yet.
- No per-user authorization exists because the gateway is still local and single-user.
- No secret manager integration exists yet.
- `basePath` is still a suggestion and not an enforced allowlist root.

## 4. Recommended Next Controls

- Add server-side audit log for every search and live tail start.
- Add file path allowlist per imported server.
- Add maximum output size and line count guardrails.
- Add WebSocket session timeout and explicit stop action.
- Move credentials into macOS Keychain or a dedicated secret manager.
- Add hostname fingerprint verification strategy beyond default SSH behavior.

## 5. Production Access Policy

Current product policy:

- FinalShell `生产` group entries must not be imported into the usable registry.
- Even if a caller knows the server id, execution must still fail at registry lookup.
- Manual server entries are controlled separately and should be reviewed before enabling production access in any future phase.
